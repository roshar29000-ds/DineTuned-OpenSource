# One controlled real-restaurant validation

This is a **local developer test**, not public Meta dispatch. The normal FastAPI app remains Meta-disabled. No live request is made by builds, tests, key presence, or the offline runner command.

## Current handoff

Taste Detective and Taste DNA feed the browser's real restaurant path. Google Places selection issues a guest-bound, one-hour branch proof. An eligible official menu source can be extracted explicitly; when no source is corroborated, the user may instead upload a text PDF or saved HTML document. Uploads retain the same signed branch identity, but are plainly labeled user-supplied and unverified as official, current, or specific to that branch. The server returns a source-linked, versioned menu and a guest-bound recommendation token. The full extracted menu appears before Picks. The signed snapshot, selected constraints, temporary refinements, and verified guest identity then enter the real Picks route. Fictional menus are never substituted. Source coverage, printed prices, ingredients, allergies, and live menu quality still need verification against an actual restaurant.

The local signing key in `.local/menu-sources/selection.key` must remain stable across the backend restart between extraction and the one-call runner. Keep the browser tab and guest session open; a new backend process reads the same key. Explicit source discovery accepts the same guest-bound, unchanged signed branch for at most six hours after selection. An explicit user file upload accepts it for up to 24 hours; other proof checks remain one hour. After that window, or for a changed guest/branch, a fresh verified selection is needed. The current Google limit is 10 search sessions per guest per UTC day; never reset the counters or create a replacement guest to evade it.

## Configuration and procedure after separate approval

1. In ignored `api/.env`, securely configure `MODEL_API_KEY` and the existing Supabase URL/publishable key. In ignored `web/.env.local`, configure the matching Supabase URL/publishable key. Keep service-role keys out of both files. The Next server uses `DINETUNED_API_URL=http://127.0.0.1:8000` by default; set it explicitly for another backend address. From `api`, `.venv/bin/python scripts/real_picks_live.py` is a **read-only offline preflight** that prints key presence and local ledger totals, never the key.
2. For the separately approved Google/website part only, set both `GOOGLE_PLACES_ENABLED=true` and `GOOGLE_PLACES_LIVE_APPROVED=true` in `api/.env`, restart the ordinary FastAPI server, and select the exact branch. One Google Autocomplete and one Details request are the intended bounds. Discover the official website/menu source, inspect branch relevance, and extract once. Stop if discovery, extraction, price evidence, or signing fails. After branch selection, set both Google flags back to `false` and stop the ordinary backend. Do not refresh the browser tab or change guest identity.
3. Copy the **guest UUID only** from Memory → Cloud status → Guest identity for local test. Never copy an access token. Confirm the selected menu and its recommendation token are still visible in the browser. With the ordinary backend stopped, start the loopback-only one-shot server from `api`: `.venv/bin/python scripts/real_picks_live.py --live --confirm-spend --user-id YOUR_GUEST_UUID`. This command is for **one separately approved paid Meta request** only. It disables Google and website jobs in that process, requires the same verified Supabase guest, and reserves at most one Meta attempt under the locked ledger. The runner uses one worker, zero SDK retries, a bounded text context, and no public network bind.
4. In the existing browser tab, click **Recheck Picks availability**, then **Find My Personal Picks** once. Inspect the returned status and citations; do not retry on errors. Stop the one-shot server immediately afterward. Inspect `.local/meta/usage.json` and the Meta billing dashboard. A failed or interrupted call may still be billed and consumes the attempt slot.

The local price estimate is a conservative upper bound, not a provider-enforced spending cap or actual invoice. The one-call upper bound is about $0.076 at the pricing snapshot dated 2026-10-28; the shared ceiling remains $10 and the 4D.5A milestone ceiling $1. Recheck official Standard Muse Spark pricing before live use and check the dashboard for external usage. The local ledger records historical attempts and must not be reset.

## Deployment boundary

Public paid dispatch is still disabled. A multi-instance deployment needs a shared durable usage ledger, distributed idempotency/rate limiting, persistent signing keys, a reviewed user consent gate, production proxy timeouts, and privacy review. Do not expose the one-call runner publicly or deploy browser fixture providers. Real menu completeness and the model's culinary quality have not been established by offline tests.
