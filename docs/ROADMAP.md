# DineTuned milestones after V2 Step 1

## Implemented foundation

Connected Next.js/FastAPI, generated validated contracts, server-owned fictional menus and ranking, complete categorized menu UX, exact budgets, combined dietary preferences, separate conservative allergy handling, optional nearby ordering, local migration/feedback, and automated checks.

## Next priorities

1. Verify real restaurant/search and authorized menu sources. Build ingestion behind the menu intelligence interface with completeness tracking, page/field evidence, versioning, and review.
2. Integrate live Taste Detective against strict structured output; validate credentials and capabilities server-side. Preserve explicit demo status on fallback.
3. Evaluate richer TasteBridge explanations against annotated sensory evidence. Measure usefulness, faithfulness, latency, and cost.
4. Add conversational refinement with explicit constraint patches; never silently remove allergies or increase budgets.
5. Add authenticated persistence and feedback observations with reversible profile updates. Do not describe preference updates as model weight training.
6. Curate verified food photography with attribution. Generated illustrations, if used, must remain visibly labeled.
7. Add production monitoring, rate limits, release CI, deployment configuration, and privacy controls.
8. Produce the cinematic welcome video once the product story and live behavior are ready.

Voice, food segmentation, self-hosted models, and complex model routing remain optional later work. None is implemented or claimed by Step 1.
