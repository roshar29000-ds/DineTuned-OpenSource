# Signature Product Experience V2

The real-menu journey and recommendation contracts are unchanged. A fresh Picks request opens **Muse's Test Kitchen**, a four-act illustration of the saved palate, extracted menu, and selection context. It closes when the actual request completes. Cached Picks open directly. The scenes do not claim to trace Muse Spark's internal reasoning or show a progress percentage.

The dedicated Picks page now uses a three-column, image-first editorial layout when three valid dishes exist. The lead selects a concise sentence from validated model text or the source menu description when the model wording is mechanical; it never adds culinary claims. Each card keeps its detailed model rationale, TasteBridge, evidence, uncertainty, and Ordered/Tried/rating controls inside **More about this pick**. Choosing and saving stay visible on the card. Complete My Table uses the backend's validated subtotal only after an explicit table selection; Worth the Stretch remains a separate above-budget alternative.

The private Muse Image cache remains guest scoped. A failed context can now read an existing valid file for the same dish and prompt identity. Unavailable images have a read-only **Check illustration** action; it never starts a generation. New generations use a more realistic, evidence-limited editorial prompt. Previously generated illustrations are reused, including earlier painterly assets, instead of incurring a new charge.

## Local, non-billable previews

Set `DINETUNED_TEST_KITCHEN_PREVIEW=true` **on the local Next.js server** and open `http://localhost:3000/culinary-orbit-preview`. The route is also restricted to loopback hosts. It displays fictional, sanitized data and never calls Google or Meta. Replay all four acts or select an act directly. Leave the flag unset in public deployment; the route returns 404. The normal application never shows these controls.

The Test Kitchen now carries a single culinary worktable through four distinct scenes: palate notes, real menu slips, conceptual matching, and a result-gated reveal. The live path uses the current Taste DNA and extracted menu; its final dish names appear only after a validated response. A fresh result enters `/picks#reveal` with a short card reveal. Returning to cached Picks enters without the cinematic replay. Use **Pause**, **Resume**, **Restart Act 1**, or **Replay sequence** in the local preview. **Clean capture** plays the sequence at reproducible preview pacing and continues to the offline Picks preview; the fixture disclosure stays visible. No progress percentage or model trace is implied.

Open `http://localhost:3000/picks-preview` for the complete featured Pick, two supporting Picks, TasteBridge, meal combination, stretch alternative, refinement controls, and isolated dining-action demonstration. It reuses the production card components with a clearly fictional extraction fixture and five locally stored, AI-generated food illustrations. These images depict only the fixture descriptions and are labeled as illustrations, never as restaurant photography. Both preview routes omit guest providers, authentication, storage writes, and paid calls. Neither preview is available on a public host or without the local flag.

The reference images in `design-references/` are local design inputs and are Git-ignored. They are not shipped or rendered as restaurant photography. The Picks layout follows their warm ivory, forest green, image-forward overview, expandable detail, horizontal meal suggestions, and refined controls. The natural-language refinement field deliberately accepts only supported phrases that map to existing temporary refinement IDs; unsupported requests send no inference call. Changing a pill alone also sends no call.

Saved guest Picks can be shown read-only when the selected menu is the same but current taste, budget, or refinements differ. The page labels this mismatch and hides dining actions until a fresh validated selection is made. An expired menu verification token blocks **new inference**, while a previously stored guest result may still be reviewed within the private table store's existing retention window. This does not extend authorization or copy results across guests. A missing illustration stays an honest placeholder with a read-only cache check; it is never regenerated during restoration. The latest inspected real cache context had two ready images and one failed image without a matching reusable file; no paid regeneration was authorized for this design pass.

Browser screenshots are generated by `web/tests/e2e/culinary-orbit-preview.spec.ts` with `E2E_TEST_KITCHEN_PREVIEW=true`; they use the offline fixture frontend. Existing private image files and usage ledgers are not committed.
